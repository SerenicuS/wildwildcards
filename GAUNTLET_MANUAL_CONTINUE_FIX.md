# Endless Gauntlet — Manual Continue Fix

## Root cause

Finisher completion called `_begin_gauntlet_transition()`, which generated the upcoming opponent immediately and armed a one-second `transition_deadline`. GameManager's `_process()` advanced automatically when that deadline expired. Space and R also advanced through the transition, including R propagating after skipping a finisher.

## Fix

- Finisher completion now enters **AWAITING_CONTINUE** and shows persistent victory results with current streak and upcoming duel number.
- Removed the automatic transition deadline, per-frame advancement, advance-by-Space behavior and R-to-continue route. Gameplay keys cannot dismiss victory results. R during a finisher skips only to results.
- **CONTINUE TO NEXT DUEL** consumes the awaiting state before generating an opponent. Only then does the existing Gauntlet generator choose cosmetics/name/arena, and the existing match-start flow resets ammunition, fatigue, selections, turn and countdown. Repeated/queued clicks are ignored in the new countdown.
- **VIEW POSTER** uses the existing WANTED presentation as a persistent read-only portrait of the defeated opponent. It has no active tween, stamp sound callback or result notification. Closing it restores the same victory screen.
- **RETURN TO MENU** uses the existing run-ending confirmation. Cancel restores the same victory results; confirm ends the run and retains achieved records.
- Defeat retains its existing persistent final-streak/personal-best screen and explicit Restart Gauntlet/Main Menu actions.

Combat resolution, streak increments, persistent records, bot AI, arena selection algorithm, difficulty/timing, cosmetics, finisher animations, Solo and Local Multiplayer mechanics were not changed.
